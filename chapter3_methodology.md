## 3.1 Research Question

This dissertation addresses the following research question, locked with the supervisor prior to prototype development and unchanged since:

> Can a small, learned adapter that projects a non-transformer perception model's internal feature representation directly into a language model's input embedding space — replacing a text-based structured interface — reduce inter-agent communication cost (tokens, latency, memory) compared to the text-based baseline, while preserving task accuracy, and what auditability cost does this trade-off impose relative to the structured text interface?

Three properties of this question shape every methodological choice that follows. First, it specifies a comparison, not a characterisation: two named interfaces, one controlled variable. Second, it names four dependent variables explicitly (tokens, latency, memory, accuracy) and treats accuracy with a qualifying clause — "while preserving" — rather than as a co-equal target metric, a distinction that governs the statistical treatment in §3.8. Third, it names auditability as an explicit, reportable cost, not an incidental limitation to be mentioned in passing.

## 3.2 Experimental Design

The design is a two-arm comparison with exactly one controlled variable: whether an event crosses the boundary between the Perception Agent and the Reasoning Agent as generated JSON text (Arm A, baseline) or as adapter-projected virtual tokens (Arm B, treatment). Every other variable that could plausibly affect the comparison is held identical across arms, summarised in Table 3.1.

**Table 3.1: Experimental controls**

| Control | Implementation | Rationale |
|---|---|---|
| Reasoning Agent weights | Identical frozen checkpoint and quantisation in both arms; no fine-tuning of the LLM itself in either arm | If training touched the LLM, the comparison would conflate interface efficiency with model adaptation |
| Perception Agent and input events | Same checkpoint, same ECG windows feed both arms | Isolates the comparison to two transmission methods for one classifier's output, not two different classifiers |
| Prompt scaffolding | Identical system prompt, output-format instructions, and fixed clinical context across both arms (see §3.9 for the one disclosed exception) | Prevents differences in instruction quality from confounding the interface comparison |
| Test set | Same held-out MIT-BIH events, same scoring rubric, both arms | Ensures both arms are evaluated on the identical task instances |
| Decoding | Greedy decoding (temperature = 0, `do_sample=False`) in both arms | Removes sampling variance as a confound, giving a clean deterministic comparison |
| Run order | Interleaved across arms (Arm A, Arm B, Arm A, Arm B, ...) rather than run in blocks | Avoids asymmetric thermal throttling or memory-caching drift accumulating in favour of whichever arm ran second |
| Timer boundaries | Clock starts when the Perception Agent's forward pass completes; stops at the Reasoning Agent's first output token | Times an identical segment of the pipeline in both arms |

## 3.3 Dataset

The MIT-BIH Arrhythmia Database (Moody and Mark, 2001) was used throughout, accessed via the `wfdb` Python library under its Open Data Commons Attribution licence, requiring no credentialing. The database comprises 48 half-hour ambulatory ECG recordings sampled at 360Hz; the four recordings containing paced beats (102, 104, 107, 217) were excluded, following standard practice, leaving 44 recordings.

Records were divided according to the inter-patient split proposed by de Chazal, O'Dwyer and Reilly (2004): DS1 (22 records) for training, DS2 (22 records) for testing, with no patient appearing in both sets. This split is deliberately more conservative than a random beat-level split, which would allow beats from the same patient's record to appear in both training and test data and inflate reported accuracy through patient-specific morphology leakage rather than genuine generalisation.

Each beat was extracted as a window of 360 samples (±180 samples, 1 second at 360Hz) centred on the R-peak location given by the database's expert annotation files, then z-score normalised per window. Beat annotations were mapped to the five-class AAMI EC57 scheme (Association for the Advancement of Medical Instrumentation, 1998) — Normal, Supraventricular ectopic, Ventricular ectopic, Fusion, and Unclassifiable — using the standard symbol mapping. Following paced-record exclusion, DS2 contains zero examples of the Unclassifiable/Q class; this is a structural property of the dataset under this split, not a sampling choice, and is treated as such throughout — no metric in this dissertation is reported for Q-class performance on DS2.

**Chronological replay for stateful fields.** The Perception Agent tracks a stateful running count of consecutive abnormal beats within a patient record (`consecutive_abnormal_beats`), which feeds both a clinical-flag field in Arm A's JSON output and the ground-truth reference label both arms are scored against. This value is only correct if beats are processed in true chronological order within each record. An early implementation selected evaluation events by index without preserving this ordering, which produced arbitrary and incorrect state for the majority of evaluated events. This was identified and corrected by replaying every index from the start of a record up to the highest selected index in true chronological order, resetting the counter at each record boundary, and retaining only the originally selected events for scoring. The correction changed reference labels for a subset of events and altered Arm A's own generated output in response — since Arm A's prompt includes the counter as an explicit field — confirming this was a substantive fix rather than a null operation, even though it did not alter the headline accuracy figures at the sample sizes tested.

## 3.4 Perception Agent Architecture

The Perception Agent is a convolutional-recurrent (CNN-LSTM) classifier, trained exclusively on the five-way AAMI classification objective with no auxiliary representation-learning loss and no large-scale pretraining. The architecture processes each 360-sample window through three one-dimensional convolutional blocks (32→64→128 channels, each with batch normalisation, ReLU activation, and max-pooling at stride 2), reshapes the resulting feature map for temporal processing, passes it through a bidirectional LSTM layer (hidden size 64), and reduces this to a fixed-length representation via a second, unidirectional context LSTM layer (hidden size 32, `return_sequences=False`). This final layer's output is a 32-dimensional context vector, produced immediately before the classification head (a dense layer with dropout, followed by a five-way softmax).

Training used a patient-level, not beat-level, internal validation split (three DS1 records held out entirely from training) — the same anti-leakage discipline applied to the DS1/DS2 test split in §3.3, and for the same reason: a beat-level random shuffle permits intra-patient morphology leakage between training and validation, which was confirmed empirically to inflate validation accuracy to 98–99% versus a true DS2 test accuracy around 85%.

This context vector is the sole quantity the adapter (§3.5) receives, extracted from the same forward pass used to produce the classification itself, at no additional computational cost. Its dimensionality and, critically, the training objective that shaped it — classification loss alone, with no incentive to preserve any information the five-way decision does not require — are directly relevant to the attribution finding presented in Chapter 4 and interpreted in Chapter 5.

## 3.5 Adapter Architecture

`VirtualTokenAdapter` is a single linear layer, `nn.Linear(32, k × 2560)`, mapping the Perception Agent's 32-dimensional context vector to `k` virtual tokens in Gemma 4 E4B's 2,560-dimensional input embedding space, reshaped to `(batch, k, 2560)`. The headline configuration uses `k = 4`, giving 337,920 trainable parameters (approximately 1.3MB in fp32) — a design choice discussed further below, not the only value tested (see the compression-ratio ablation, §4.6).

Two properties of this architecture are stated here because they carry direct interpretive weight in Chapter 5, not merely as implementation detail. First, the projection is a single linear map from a 32-dimensional input, and is therefore rank-limited to at most 32 regardless of its output width: it cannot represent, encode, or introduce information beyond what its 32-dimensional input already contains. This is a mathematical property of the architecture, not an empirical finding, and it is the basis for the a priori prediction — tested and confirmed in §4.5 — that any information ceiling observed in the adapter's output reflects the Perception Agent's representation, not the adapter itself.

Second, weight initialisation follows `nn.init.normal_(weight, mean=0.0, std=0.02/√32)` with zero bias — chosen to approximate the scale of a genuine token embedding at model initialisation, rather than an arbitrarily large random soft prompt. This choice, and whether training preserves or disturbs it, is examined directly in the adapter internal-properties check (§4.7) and is relevant to the off-manifold discussion in Chapter 5.

Training used full canonical-JSON teacher forcing — next-token prediction across the complete structured output the Reasoning Agent is expected to produce, not a narrower loss restricted to the urgency-tier field alone, since a narrower loss would leave the model's schema and justification behaviour untested at training time while still being scored on it at evaluation time. The loss was tier-weighted (`L = 4·L_tier + L_rest`) to prioritise the clinically load-bearing field without discarding the rest of the structured output from training entirely. Optimisation used AdamW restricted to the adapter's own parameters; every Reasoning Agent parameter was frozen (`requires_grad_(False)`) and the model held in evaluation mode throughout adapter training, consistent with the "no fine-tuning of the LLM" control in Table 3.1.

## 3.6 Reasoning Agent

The Reasoning Agent is Gemma 4 E4B (`google/gemma-4-E4B-it`), loaded via HuggingFace `transformers` with 4-bit (NF4) quantisation through `bitsandbytes`, and held frozen throughout — no fine-tuning is applied to either arm's interface. Both arms share a single loaded model instance, satisfying the identical-checkpoint-and-quantisation control in Table 3.1.

`transformers` with `bitsandbytes` was used in preference to a production-optimised serving engine (e.g. Ollama or llama.cpp) because those engines expose no equivalent of an `inputs_embeds` argument — they accept only tokenised text as generation input, which is incompatible with Arm B's requirement to inject continuous virtual-token vectors directly. This is a disclosed limitation: `transformers`+`bitsandbytes` is markedly slower in absolute decoding terms than a production-optimised engine for single-request inference. Because both arms share this inefficiency equally, the *relative* comparison between arms remains valid; only the *absolute* latency magnitude reported in Chapter 4 should be read as inflated relative to a production deployment, and is not claimed to represent production-grade serving latency.

**Architectural constraint: Per-Layer Embeddings.** Gemma 4 uses Per-Layer Embeddings (PLE), an additional per-token, per-layer embedding contribution retrieved via a lookup table keyed on vocabulary token ID, supplementing the standard input embedding every real text token receives. Virtual tokens have no vocabulary ID and therefore cannot be given a genuine PLE lookup; if `per_layer_inputs` is not supplied explicitly, the model attempts to derive it by comparing continuous input embeddings against the entire 262,144-token vocabulary table, which for virtual-token positions produces a broadcast operation requesting an allocation on the order of 196GB and fails immediately with a CUDA out-of-memory error. This was encountered directly during development. The implemented fix constructs `per_layer_inputs` explicitly via a surrogate padding-token-ID sequence at virtual-token positions, passed to both the forward pass (training) and generation calls. This resolves the immediate failure, but does not resolve the underlying architectural asymmetry, which is disclosed formally in §3.9.

## 3.7 Metrics and Measurement Methodology

Four dependent variables are measured directly from the two arms, plus one derived quantity assessed via a separate diagnostic protocol.

**Token count** is the number of tokens comprising the Reasoning Agent's input in each arm (the full prompt for Arm A; the fixed textual scaffold plus `k` virtual-token positions for Arm B), counted via the model's own tokenizer.

**Generation latency** is measured end-to-end from the timer boundary specified in Table 3.1 to completion of generation, using wall-clock time under greedy decoding.

**VRAM footprint** is measured using PyTorch's own allocator statistics — `torch.cuda.reset_peak_memory_stats()` before each arm's call, `torch.cuda.max_memory_allocated()` after — in preference to an `nvidia-smi` delta. This is a deliberate methodological choice: PyTorch's allocator stats isolate the peak memory attributable to the specific call under measurement, whereas whole-GPU `nvidia-smi` readings include OS- and driver-level overhead that is not attributable to either arm and would introduce measurement noise unrelated to the interface comparison.

**Task accuracy** is scored against a deterministic reference tier derived from the event's true classification and clinical flags, compared to each arm's generated urgency-tier output.

**Auditability** is assessed via a held-out linear-probe protocol, not as a byproduct of the accuracy metric above. A probe classifier is trained to recover the AAMI class label from the adapter's output vector (for Arm B) or, for the attribution comparison in §4.5, from the Perception Agent's raw 32-dimensional context vector directly. Evaluation uses repeated stratified k-fold cross-validation (5 folds × 3 repeats) with dimensionality reduced to 30 principal components before classification, fit inside the cross-validation pipeline per fold to avoid leakage from held-out data into the transform. This component count is not an arbitrary choice: because the adapter is a single linear map from a 32-dimensional input (§3.5), its output provably lives in an affine subspace of rank at most 32 regardless of its raw 10,240-dimensional width, so a PCA reduction to 30 components — deliberately set just below this structural ceiling — avoids fitting noise in dimensions the adapter's own construction guarantees carry no additional information. A fixed chance baseline of 25% applies throughout (four-way classification; Q is absent from DS2, per §3.3). This cross-validated protocol supersedes an earlier single-split evaluation, which proved to be a fragile point estimate; the cross-validated version is the version reported in Chapter 4. A paired Wilcoxon signed-rank test compares fold-level scores between the adapter-output probe and the raw-context-vector probe directly, forming the attribution result reported in §4.5.

## 3.8 Statistical Treatment

Two interpretive commitments are stated here, before any result from Chapter 4 is referenced, so that the statistical framing is demonstrably a consequence of the research question's structure rather than a post hoc response to the data obtained.

**Accuracy is treated as a constraint check, not a co-primary endpoint.** The research question's own clause — "while preserving task accuracy" — subordinates accuracy to the primary claims about communication cost. Accordingly, the primary inferential claims in this dissertation concern token count and latency, tested via paired Wilcoxon signed-rank tests on per-event measurements across both arms. Accuracy is evaluated separately, as a check on whether the efficiency gains come at a resolvable cost, with its magnitude and uncertainty reported explicitly rather than treated as a headline result in its own right.

**Accuracy is reported confidence-interval-forward, with a structural correction to the significance test.** Arm A attained 100% accuracy (80/80) on the evaluation set used in Chapter 4. This has a direct consequence for hypothesis testing: a McNemar contingency table comparing the two arms is structurally guaranteed to have an empty discordant cell in one direction (Arm A cannot contribute an "Arm A incorrect, Arm B correct" pair, since it has no incorrect predictions to contribute), independent of the actual data. A two-sided exact McNemar test nonetheless allocates probability mass toward this structurally impossible direction, which is not the appropriate instrument here. The one-sided exact test, justified a priori by Arm A's ceiling performance rather than selected after observing the result, is reported as the directional significance test. In addition, and as the primary reporting format, both arms' accuracies are reported with exact 95% confidence intervals (Clopper-Pearson for Arm A's ceiling case; Wilson for Arm B), so that any accuracy difference is presented as a bounded, honestly-uncertain quantity rather than a single point estimate whose apparent precision the sample size does not support.

## 3.9 Disclosed Asymmetries

Two asymmetries exist between the two arms beyond the single controlled variable named in §3.2. Both are disclosed here, as methodology, because both are deliberate engineering decisions with a documented rationale, not oversights discovered after the fact.

**Per-Layer Embeddings are unavailable to virtual tokens (§3.6).** Real text tokens in both arms receive Gemma 4's full architectural pathway, including the PLE contribution; Arm B's virtual tokens receive only a surrogate padding-identity PLE lookup, since PLE is a discrete lookup table with no defined mechanism for accepting a continuous vector. This is a genuine, disclosed cost of the adapter approach at the architecture level, distinct from and additional to the auditability cost measured in §3.7, and is treated as such in the Discussion (Chapter 5).

**Fixed clinical context differs in specificity between arms.** Arm A's context-injection block is legitimately class-specific: its heading names the predicted AAMI class explicitly, which is defensible because Arm A's JSON payload already carries that class as content the Reasoning Agent can read directly. An earlier implementation of Arm B reused this same class-specific heading unchanged, which meant the heading alone — entirely independent of the virtual tokens — carried sufficient information to solve the classification-dependent portion of the task, since the heading's class was drawn from the same field the training target and reference label are built from. This was identified as a genuine leak, not a design choice: it invalidated any accuracy or training-loss result computed before the fix. The correction replaces Arm B's context block with a single class-neutral formulation covering the same escalation logic across all classes without naming which applies, verified by regression test to be byte-identical regardless of the predicted class. This is now a disclosed, deliberate asymmetry — Arm A's context is class-specific, Arm B's is class-neutral — retained because Arm A has a legitimate channel for the class that Arm B does not, not because it was overlooked.

## 3.10 Gap Verification and Falsification Search Protocol

The literature gap motivating this dissertation (Chapter 1, §1.3; Chapter 2, §2.5) was tested against a specific falsification candidate before being accepted as unaddressed. The candidate: any published work combining (i) a non-transformer encoder trained discriminatively only, with no representation-learning pretraining or contrastive objective; (ii) a frozen, zero-shot receiving language model, with no fine-tuning or adapter training on the receiver side; and (iii) an explicit measurement of communication efficiency or auditability cost. If any published work satisfies all three properties simultaneously, the gap claim as stated does not hold.

Four search paths were pursued specifically to locate a counterexample, rather than to accumulate supporting citations: Flamingo's non-transformer vision encoder (Alayrac et al., 2022), confirmed to use gated cross-attention injection rather than embedding-space projection, and therefore not satisfying the mechanism this dissertation characterises; Wong et al. (2025), whose CNN encoder is projected into an LLM's embedding space for fetal monitoring, but whose encoder is contrastively pretrained (failing criterion i) and whose receiver is fine-tuned via LoRA (failing criterion ii); an EEG reprogramming approach using Time-LLM-style cross-attention prototype alignment rather than direct embedding injection; and Vision Wormhole (2026), which shares this dissertation's framing vocabulary closely but transmits transformer-produced hidden states through a vision-channel injection point, failing criterion i outright. No source located across these four paths satisfies the full conjunction. The gap is treated as verified, not assumed, on this basis, and is reported as a narrowed conjunction (Chapter 1, §1.3) precisely because each near-miss source is distinguished on a specific, named axis rather than dismissed generically.
